Backend & System Design — Interview Notes

Quick-reference Q&A across distributed systems, infra, databases, security, and ops.

Traffic, Caching & Edge

What is Rate Limiting and what are common algorithms?Q1

Rate limiting restricts how many requests a client can make in a time window, protecting services from abuse and overload.

  • Token Bucket — tokens refill at a fixed rate; each request consumes a token, allows bursts.
  • Leaky Bucket — requests processed at a constant rate; smooths bursts.
  • Fixed Window — simple counter per time window; can allow bursts at window edges.
  • Sliding Window Log/Counter — more accurate, avoids edge-burst problem, costlier to compute.
What is Caching and what strategies exist?

Caching stores frequently accessed data in a faster layer to reduce latency and backend load.

  • Cache-aside (lazy load) — app checks cache first, loads from DB on miss, then populates cache.
  • Write-through — writes go to cache and DB together; consistent but slower writes.
  • Write-back — writes go to cache first, flushed to DB later; fast but risk of data loss.
  • Read-through — cache itself is responsible for loading from DB on miss.
What is Cache Invalidation and why is it hard?

Cache invalidation is the process of removing or updating stale cache entries when underlying data changes. It's considered one of the two hard problems in computer science because it requires balancing freshness against performance.

  • TTL expiry — simplest, but data can be stale until expiry.
  • Explicit invalidation — delete/update cache on write; needs careful coordination across services.
  • Versioned keys — bump a version/hash in the cache key so old entries become naturally unreachable.
What is a Load Balancer and what algorithms does it use?

A load balancer distributes incoming traffic across multiple backend instances to improve availability and throughput.

  • Round Robin / Weighted Round Robin — cycles through servers, optionally weighted by capacity.
  • Least Connections — sends traffic to the server with fewest active connections.
  • IP Hash / Consistent Hash — routes based on client identity, useful for session affinity.
  • Layer 4 (TCP/UDP) balances at the transport layer; Layer 7 (HTTP) balances with content awareness (path, headers).
What's the difference between a Reverse Proxy and an API Gateway?

A Reverse Proxy sits in front of servers, forwarding client requests and handling concerns like SSL termination, load balancing, and caching — it's largely transparent about business logic.

An API Gateway is a specialized reverse proxy for APIs that adds routing to multiple microservices, authentication, rate limiting, request/response transformation, and aggregation of multiple backend calls into one client-facing response.

What is a CDN and what is Edge Caching?

A CDN (Content Delivery Network) is a geographically distributed set of servers that cache and serve content close to end users, reducing latency and origin load.

Edge caching refers to caching data or even compute at these edge nodes so requests never have to travel back to a central origin server — useful for static assets, API responses, and increasingly edge functions.

DevOps, Containers & Deployment

What is CI/CD?

Continuous Integration is the practice of frequently merging code into a shared branch, with automated builds and tests running on every change to catch issues early.

Continuous Delivery/Deployment automates the release pipeline so validated changes can be shipped to staging/production quickly and reliably, either with a manual approval gate (delivery) or fully automatically (deployment).

What is Docker and how does it differ from a VM?

Docker packages an application with its dependencies into a lightweight, portable container that shares the host OS kernel, unlike a Virtual Machine which virtualizes an entire OS and hardware stack.

Containers start in seconds, use far less memory/disk, and give consistent environments across dev, test, and prod — at the cost of weaker isolation compared to VMs.

What is Kubernetes and what problem does it solve?

Kubernetes (K8s) is a container orchestration platform that automates deployment, scaling, networking, and self-healing of containerized applications across a cluster of machines.

  • Pod — smallest deployable unit, one or more containers.
  • Deployment — manages replica sets and rolling updates.
  • Service — stable network endpoint for a set of pods.
  • ConfigMap/Secret — externalized configuration and sensitive values.
What is Service Discovery?

Service discovery lets services find each other's network locations dynamically in environments where instances are frequently created, destroyed, or rescheduled (e.g., Kubernetes, autoscaling groups).

  • Client-side discovery — client queries a registry (e.g., Consul, Eureka) and load-balances itself.
  • Server-side discovery — client calls a load balancer/router which queries the registry (typical in K8s via DNS + Services).
What is Infrastructure as Code (IaC)? What are Terraform and Helm Charts?

IaC means defining and provisioning infrastructure through machine-readable config files instead of manual processes — enabling versioning, review, and repeatability.

Terraform is a declarative, cloud-agnostic IaC tool that manages resources (VMs, networks, DNS, etc.) via a state file and provider plugins.

Helm Charts package Kubernetes manifests as reusable, parameterized templates — the de-facto "package manager" for K8s applications.

What are Blue-Green, Canary, and Rolling Deployments?
  • Blue-Green — two identical environments; traffic is switched entirely from old (blue) to new (green) at once, enabling instant rollback.
  • Canary — new version is released to a small subset of traffic/users first, gradually increased if healthy.
  • Rolling Deployment — instances are updated incrementally, a few at a time, so the app stays available throughout.

All three aim to minimize downtime and blast radius; Rollback is the act of reverting to the previous known-good version when a deployment misbehaves.

What are Health Checks and Liveness/Readiness Probes?

A health check is an endpoint or mechanism that reports whether a service instance is functioning correctly.

  • Liveness probe — asks "is this process alive?" If it fails repeatedly, the orchestrator restarts the container.
  • Readiness probe — asks "is this instance ready to receive traffic?" If it fails, the instance is removed from the load balancer pool but not restarted.
What is Autoscaling, Horizontal vs Vertical Scaling?

Autoscaling automatically adjusts the number (or size) of running instances based on metrics like CPU, memory, or request rate.

Horizontal scaling (scale out) adds more instances/machines — better for fault tolerance and near-limitless growth. Vertical scaling (scale up) adds more resources (CPU/RAM) to an existing instance — simpler but has a hardware ceiling and a single point of failure.

What are Cold Starts and Serverless Limits?

A cold start is the added latency when a serverless function (e.g., AWS Lambda) has to initialize a new execution environment because none is warm/idle, as opposed to a "warm" invocation reusing an existing one.

Serverless limits include maximum execution duration, memory/CPU caps, payload size limits, limited local disk, and cost/latency tradeoffs for long-running or stateful workloads — meaning serverless suits short, bursty, stateless tasks best.

Resilience Patterns

What is a Circuit Breaker pattern?

A circuit breaker prevents a failing downstream service from being hammered with requests, by "tripping open" after a failure threshold and short-circuiting calls (failing fast) for a cooldown period.

  • Closed — requests flow normally.
  • Open — requests fail immediately without calling downstream.
  • Half-Open — a few test requests are allowed through to check if the dependency recovered.
What's the difference between Timeouts, Retries, and Exponential Backoff?

Timeouts bound how long a caller waits for a response before giving up, preventing threads/connections from hanging indefinitely.

Retries re-attempt a failed operation, useful for transient errors — but naive retries can amplify load during an outage ("retry storm").

Exponential backoff increases the wait time between retries exponentially (often with jitter/randomness added) to spread out retry attempts and avoid overwhelming a recovering service.

What is Idempotency and why does it matter?

An operation is idempotent if performing it multiple times has the same effect as performing it once — critical for safe retries in distributed systems where a client can't always tell if a request actually succeeded.

Common technique: an idempotency key (client-generated unique ID) sent with a request; the server stores results keyed by that ID and returns the cached result on duplicate submissions instead of re-processing (e.g., preventing double payment charges).

What is Backpressure?

Backpressure is a mechanism for a system to signal upstream producers to slow down when it can't keep up with the incoming rate of work, preventing memory exhaustion or cascading failure.

Implementations include bounded queues that reject or block on overflow, reactive streams with demand signaling, and HTTP-level flow control in protocols like HTTP/2.

What is Chaos Engineering?

Chaos engineering is the practice of deliberately injecting failures (killing instances, adding network latency, simulating region outages) into a system, typically in production, to proactively discover weaknesses before they cause real incidents.

Popularized by Netflix's Chaos Monkey; done carefully with a hypothesis, blast-radius control, and monitoring in place.

What is Disaster Recovery, and what are Backups vs Failover vs Multi-Region?

Disaster Recovery (DR) is the strategy and processes for restoring service after a major failure (data center outage, corruption, region loss).

  • Backups — periodic copies of data to restore from; measured by RPO (how much data you can lose) and RTO (how fast you can recover).
  • Failover — automatic or manual switch to a standby system when the primary fails.
  • Multi-Region Deployment — running active infrastructure in multiple geographic regions for both lower latency and resilience against a whole-region outage.

Messaging & Event-Driven Systems

What is a Message Queue and how does it differ from Pub/Sub?

A Message Queue (e.g., RabbitMQ, SQS) delivers each message to exactly one consumer, typically used for task distribution/work queues.

Pub/Sub (e.g., Kafka topics, SNS) broadcasts each message to all subscribed consumers/topics, decoupling producers from an arbitrary number of interested consumers.

What is Event-Driven Architecture?

An architectural style where services communicate by producing and reacting to events (facts about something that happened) rather than direct synchronous calls, improving decoupling and scalability.

Trade-offs include eventual consistency, harder debugging/tracing across async flows, and the need for idempotent event handlers since events can be delivered more than once.

What are Distributed Transactions and the Saga Pattern?

A distributed transaction spans multiple services/databases and needs all-or-nothing semantics, but classic two-phase commit (2PC) doesn't scale well across microservices.

The Saga pattern breaks a distributed transaction into a sequence of local transactions, each with a compensating action to undo it if a later step fails — implemented either via choreography (services react to each other's events) or orchestration (a central coordinator directs the steps).

What is a Dead Letter Queue (DLQ)?

A DLQ is a separate queue where messages are routed after they repeatedly fail processing (exceeding a retry limit), so they don't block the main queue or get silently dropped.

It lets engineers inspect, debug, and potentially replay failed messages without impacting the throughput of healthy message processing.

What are Cron Jobs?

Cron jobs are scheduled tasks that run automatically at fixed times or intervals (e.g., nightly reports, cleanup jobs). In distributed systems, care is needed to avoid duplicate execution across multiple instances — typically solved with distributed locks or a dedicated scheduler like Quartz.NET.

What are Webhooks?

Webhooks are user-defined HTTP callbacks: instead of a client polling for updates, the server sends an HTTP POST to a client-provided URL when an event occurs, enabling real-time, push-based integration between systems.

Reliable implementations include signature verification (HMAC), retries with backoff, and idempotency handling on the receiver side.

Real-Time Communication & Protocols

WebSockets vs Long Polling vs Server-Sent Events — what's the difference?
  • WebSockets — a persistent, full-duplex TCP connection allowing both client and server to send messages anytime; best for chat, gaming, live collaboration.
  • Long Polling — client sends a request, server holds it open until new data is available (or timeout), then client immediately re-requests; simulates real-time over plain HTTP.
  • Server-Sent Events (SSE) — a one-way stream from server to client over HTTP, simpler than WebSockets, good for live feeds/notifications that don't need client-to-server push.
TCP vs UDP — key differences?

TCP is connection-oriented, guarantees ordered and reliable delivery via acknowledgments and retransmission — used for HTTP, file transfer, email.

UDP is connectionless with no delivery guarantees or ordering, but has lower overhead and latency — used for video streaming, gaming, DNS, and VoIP where speed matters more than perfect reliability.

What's new in HTTP/2 and HTTP/3?

HTTP/2 introduced multiplexing (many requests over one TCP connection, fixing head-of-line blocking at the HTTP layer), header compression (HPACK), and server push.

HTTP/3 runs over QUIC (built on UDP) instead of TCP, eliminating TCP-level head-of-line blocking, enabling faster connection setup, and better performance on unreliable networks.

What is gRPC?

gRPC is a high-performance RPC framework built on HTTP/2 that uses Protocol Buffers for compact, strongly-typed binary serialization. It supports unary calls plus streaming (client, server, and bidirectional), making it popular for internal microservice-to-microservice communication where performance matters more than human-readability (vs REST/JSON).

What is DNS and how does resolution work?

DNS (Domain Name System) translates human-readable domain names into IP addresses through a hierarchical, distributed lookup: recursive resolver → root servers → TLD servers → authoritative name server.

Caching (via TTLs) happens at multiple layers (browser, OS, ISP resolver) to reduce lookup latency; DNS is also commonly used for load balancing and service discovery.

Databases & Data Layer

What is Database Indexing and how does it help Query Optimization?

An index is a separate data structure (commonly a B-tree or hash) that lets the database find rows without scanning the entire table, dramatically speeding up reads at the cost of extra storage and slower writes (since indexes must also be updated).

Query optimization involves choosing the right indexes, analyzing execution plans, avoiding unnecessary columns/joins, and rewriting queries so the optimizer can use indexes effectively (e.g., avoiding functions on indexed columns in WHERE clauses).

What is the N+1 Query problem?

The N+1 problem occurs when code fetches a list of N parent records with one query, then issues a separate query per record to fetch related data — resulting in N+1 total queries instead of a single join or batched query.

Fixed via eager loading/joins (e.g., Include() in EF Core), batching, or DataLoader-style patterns.

What is Connection Pooling?

Connection pooling reuses a set of pre-established database connections instead of opening/closing a new TCP + auth handshake per request, which is expensive. A pool manager hands connections out to threads and returns them when done, controlling max concurrency to the DB.

Read Replicas vs Sharding vs Partitioning vs Replication — how do they differ?
  • Replication — copying data across multiple database nodes for redundancy and read scaling (leader-follower or multi-leader setups).
  • Read Replicas — a specific replication use case: read-only copies that offload read traffic from the primary/leader, which still handles all writes.
  • Partitioning — splitting a large table into smaller pieces (partitions) within the same database, often by range or list, to improve manageability and query performance.
  • Sharding — a form of horizontal partitioning where data is split across multiple separate database instances/servers, each holding a subset of data (e.g., by user ID hash), enabling near-limitless horizontal scale.
What are Database Migrations and Schema Versioning?

Migrations are versioned, incremental scripts that evolve a database schema over time (add column, create index, etc.) in a repeatable, trackable way, usually applied via tooling (EF Core Migrations, Flyway, Liquibase).

Schema versioning ensures every environment's database structure can be traced to a specific version in source control, supporting rollbacks and safe team collaboration.

Distributed Systems Theory

What is the CAP Theorem?

CAP theorem states that a distributed data store can only guarantee two of three properties simultaneously during a network partition:

  • Consistency — every read receives the most recent write.
  • Availability — every request receives a (non-error) response.
  • Partition Tolerance — the system continues to operate despite network failures between nodes.

Since network partitions are unavoidable in real distributed systems, the practical choice is between CP (consistent but may reject requests during a partition) and AP (available but may return stale data).

What is Eventual Consistency?

Eventual consistency guarantees that if no new updates are made, all replicas will eventually converge to the same value — but reads immediately after a write might return stale data. It trades strict consistency for higher availability and lower latency, common in NoSQL systems like DynamoDB and Cassandra.

What is Leader Election?

Leader election is the process by which nodes in a distributed system agree on a single coordinator ("leader") responsible for a task (e.g., accepting writes, scheduling jobs), even in the presence of failures.

Algorithms/tools: Raft, Paxos, or coordination services like ZooKeeper/etcd that use consensus protocols to ensure only one leader is active at a time.

Optimistic Locking vs Pessimistic Locking?

Pessimistic locking acquires a lock on data before reading/modifying it, blocking other transactions until released — safe but can hurt concurrency and risks deadlocks.

Optimistic locking assumes conflicts are rare: it lets transactions proceed without locking, then checks a version/timestamp column at commit time to detect conflicts, retrying if another transaction changed the data first.

What are Distributed Locks?

A distributed lock coordinates exclusive access to a shared resource across multiple processes/machines (not just threads in one process), commonly implemented with Redis (SET NX PX), ZooKeeper, or etcd.

Key challenges: handling lock expiry vs. process pauses (GC, network delay) safely — the Redlock algorithm and fencing tokens are common mitigations.

Race Conditions vs Deadlocks — what's the difference?

A race condition occurs when the outcome of a program depends on the unpredictable timing/interleaving of concurrent operations, leading to inconsistent results (e.g., two threads incrementing a counter without synchronization).

A deadlock occurs when two or more processes each hold a resource the other needs and wait forever, with no thread able to proceed — commonly caused by inconsistent lock ordering.

What are Network Partitions and Clock Skew?

A network partition ("split-brain") happens when a network failure divides a cluster into groups that can't communicate with each other, forcing a choice between consistency and availability (see CAP theorem).

Clock skew is the difference between clocks on different machines; since distributed systems can't rely on perfectly synchronized wall clocks, techniques like logical clocks (Lamport timestamps), vector clocks, or hybrid clocks (Google's TrueTime) are used to order events correctly.

Concurrency & Memory

What are Memory Leaks and how does Garbage Collection relate?

A memory leak occurs when a program allocates memory it no longer needs but never releases it, gradually exhausting available memory — common causes include unsubscribed event handlers, static references, and caches without eviction.

Garbage Collection (GC) automatically reclaims memory for objects no longer reachable from program roots (e.g., .NET's generational GC), but it doesn't prevent all leaks — objects still referenced (even unintentionally) will never be collected.

What is Thread Safety?

Code is thread-safe if it behaves correctly when accessed by multiple threads concurrently, without requiring external synchronization from the caller. Achieved via locks/mutexes, immutable data structures, thread-local storage, or lock-free/atomic operations (e.g., Interlocked in C#).

Observability & Monitoring

Monitoring vs Logging vs Distributed Tracing — how do they differ?
  • Monitoring — collecting and visualizing metrics (CPU, request rate, error rate) to understand system health over time.
  • Logging — recording discrete events with context, used for debugging and audit trails.
  • Distributed Tracing — tracks a single request as it flows across multiple services, giving a timeline (spans) to pinpoint where latency or errors occur in a microservices call chain (e.g., OpenTelemetry, Jaeger).

Together with Metrics, these three form the "pillars of Observability" — the ability to infer internal system state from external outputs.

What is Alerting and how does it relate to SLOs, SLIs, and Error Budgets?
  • SLI (Service Level Indicator) — a measured metric, e.g., request latency or error rate.
  • SLO (Service Level Objective) — a target for an SLI, e.g., "99.9% of requests succeed."
  • Error Budget — the allowed amount of failure (100% − SLO) before violating the SLO; used to balance reliability work against feature velocity.

Alerting notifies engineers when metrics cross thresholds that put SLOs at risk, ideally tuned to minimize noise (alert fatigue) while catching real issues.

Latency vs Throughput, and what is P99/Tail Latency?

Latency is the time to complete a single request; Throughput is the number of requests a system can handle per unit time. They're related but distinct — a system can have high throughput with high latency (batching) or low latency with limited throughput.

P99 latency is the value below which 99% of requests complete — i.e., the worst 1% take longer. Tail latency refers to this slow end of the distribution; it matters because average latency can look great while a meaningful fraction of users have a bad experience.

Security

What is Secrets Management and IAM?

Secrets management is the secure storage, rotation, and access control of sensitive values (API keys, passwords, certificates) using tools like Vault, AWS Secrets Manager, or Azure Key Vault — instead of hardcoding them in source or config files.

IAM (Identity and Access Management) is the framework for defining who (users, services) can access what resources, typically via roles and policies following the principle of least privilege.

What is OAuth and how does JWT rotation work?

OAuth 2.0 is an authorization framework that lets a user grant a third-party application limited access to their resources without sharing credentials, using tokens issued by an authorization server.

JWT (JSON Web Token) is a self-contained, signed token often used as an OAuth access token. JWT rotation refers to using short-lived access tokens paired with longer-lived refresh tokens, periodically issuing new tokens and invalidating old ones to limit the damage window if a token is compromised.

TLS, Encryption at Rest, and Encryption in Transit — what's the difference?

TLS (Transport Layer Security) encrypts data as it travels over the network (the mechanism behind HTTPS), protecting against eavesdropping and tampering — this is encryption in transit.

Encryption at rest protects stored data (databases, disks, backups) so that if storage media is stolen or accessed improperly, the data remains unreadable without the decryption key.

What are WAF and DDoS Protection?

A WAF (Web Application Firewall) inspects HTTP traffic and blocks common application-layer attacks (SQL injection, XSS, malicious bots) based on rules or ML-based detection.

DDoS protection mitigates Distributed Denial of Service attacks — floods of traffic meant to overwhelm a service — using techniques like traffic scrubbing, rate limiting, and large-scale edge/CDN absorption capacity.

CORS vs CSRF — what's the difference?

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that restricts which origins (domains) are allowed to make requests to a given API, controlled by server-sent headers like Access-Control-Allow-Origin.

CSRF (Cross-Site Request Forgery) is an attack where a malicious site tricks a logged-in user's browser into making an unwanted authenticated request to another site. Defended against with CSRF tokens, SameSite cookies, and checking request origins.

SQL Injection, XSS, and SSRF — what are they?
  • SQL Injection — attacker inserts malicious SQL through unsanitized input, potentially reading/modifying/destroying data. Prevented with parameterized queries/ORMs.
  • XSS (Cross-Site Scripting) — attacker injects malicious scripts into pages viewed by other users. Prevented by output encoding and Content Security Policy.
  • SSRF (Server-Side Request Forgery) — attacker tricks the server into making requests to internal/unintended resources (e.g., cloud metadata endpoints) via a server-side fetch feature. Prevented with strict allow-lists and network segmentation.

API Design

What is API Versioning and Semantic Versioning?

API versioning lets an API evolve without breaking existing clients, commonly via URL path (/v1/), header, or query parameter — allowing old and new versions to coexist during a migration window.

Semantic Versioning (SemVer) uses a MAJOR.MINOR.PATCH scheme where MAJOR bumps signal breaking changes, MINOR adds backward-compatible functionality, and PATCH is for backward-compatible bug fixes — giving consumers a predictable signal of impact.

Operations & Delivery Practices

What are Feature Flags?

Feature flags (toggles) let teams enable/disable functionality at runtime without deploying new code, supporting gradual rollouts, A/B testing, kill-switches for risky features, and decoupling deployment from release.

What is Cost Optimization in cloud/backend systems?

Cost optimization involves right-sizing infrastructure (avoiding over-provisioning), using autoscaling, choosing appropriate pricing models (reserved vs on-demand vs spot instances), efficient caching to reduce compute/DB load, and monitoring spend with tools/dashboards to catch waste (idle resources, oversized instances, unused storage).

What are Production Incidents, On-call, and Postmortems?

A production incident is an unplanned event impacting service availability or correctness, typically triaged by severity and resolved via an incident response process (detect → mitigate → resolve).

On-call is a rotation where an engineer is responsible for responding to alerts/incidents outside normal hours.

A postmortem (or retrospective) is a blameless written analysis after an incident covering root cause, timeline, impact, and concrete follow-up action items to prevent recurrence.

What is Dependency Hell?

Dependency hell refers to problems arising from conflicting or incompatible versions of libraries/packages a project depends on — e.g., two dependencies requiring different major versions of the same shared library. Mitigated with lockfiles, semantic versioning discipline, dependency isolation (containers, virtual environments), and regular, incremental upgrades rather than large infrequent ones.
