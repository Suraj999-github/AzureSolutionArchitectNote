🚦 Traffic Management & APIs
🚦
Rate Limiting ▼
Q: What is Rate Limiting and why is it needed?
Rate limiting controls how many requests a client can make to an API within a time window. It prevents abuse, DDoS, resource exhaustion, and ensures fair usage across tenants.
Q: Name common rate-limiting algorithms.
Token Bucket (tokens refill at steady rate, burst allowed), Leaky Bucket (constant outflow, smooths bursts), Fixed Window (simple but boundary issues), Sliding Window Log/Counter (more accurate, Redis Sorted Sets).
Q: How do you communicate rate limits to clients?
Via HTTP headers: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset, and Retry-After. Return 429 Too Many Requests when exceeded.

Caching ▼
Q: What are common caching strategies?
Cache-Aside (app checks cache first, loads DB on miss), Write-Through (write to cache & DB simultaneously), Write-Behind (write to cache, async flush to DB), Read-Through (cache handles DB fetch).
Q: What is Cache Invalidation and why is it hard?
Removing stale data when the source changes. Strategies: TTL-based expiration, event-driven invalidation, write-through updates. The famous quote: "There are only two hard things in CS: naming things and cache invalidation."
Q: What is the difference between Redis and Memcached?
Redis supports richer data structures (lists, sets, sorted sets, streams), persistence, replication, and Lua scripting. Memcached is simpler, purely key-value, multi-threaded, and can be faster for basic workloads.
RedisTTLCache-Aside

Load Balancing ▼
Q: What are common load balancing algorithms?
Round Robin (sequential), Least Connections (fewest active), Least Response Time, IP Hash (sticky sessions), Weighted variants. Layer 4 (TCP) vs Layer 7 (HTTP/application-level).
Q: What is the difference between L4 and L7 load balancers?
L4 operates at TCP/UDP level, faster but no content inspection. L7 understands HTTP, can route based on headers/paths, terminate TLS, and make smarter decisions. Nginx/HAProxy do L7; cloud NLB is L4.
NginxHAProxyL4 vs L7

Reverse Proxy ▼
Q: What does a Reverse Proxy do?
Sits in front of backend servers, handling TLS termination, caching, compression, authentication, request routing, and DDoS protection. Clients only see the proxy, never the origin servers directly.
Q: Reverse Proxy vs Forward Proxy?
Forward proxy sits in front of clients (e.g., corporate proxy, VPN), routing outbound requests. Reverse proxy sits in front of servers, handling inbound traffic. Different sides of the connection.
NginxTLS TerminationGateway
🌐
API Gateway ▼
Q: What is an API Gateway and its key features?
A single entry point for all client requests. Handles auth, rate limiting, request/response transformation, routing, API composition, logging, and monitoring. Examples: Kong, Apigee, AWS API Gateway, Envoy.
Q: API Gateway vs Load Balancer vs Reverse Proxy?
They overlap but serve different primary purposes: LB distributes traffic; Reverse Proxy shields servers; API Gateway adds API management features (auth, rate limiting, documentation, versioning, monetization). Modern gateways often include LB & proxy features.
KongApigeeMicroservices
🔄 CI/CD & Containerization
🔁
CI/CD ▼
Q: What's the difference between CI, CD (Delivery), and CD (Deployment)?
CI: frequently merge code, auto-build & test. Continuous Delivery: every change is deployable, but manual approval to prod. Continuous Deployment: every passing change auto-deploys to production without manual gates.
Q: What are common CI/CD tools?
Jenkins, GitHub Actions, GitLab CI/CD, CircleCI, ArgoCD (GitOps for K8s), Spinnaker, Tekton. Key pipeline stages: Build → Test → Security Scan → Deploy → Monitor.
JenkinsGitHub ActionsArgoCD
🐳
Docker ▼
Q: Container vs Virtual Machine?
Containers share the host OS kernel, are lightweight (MBs), start in seconds. VMs each have a full guest OS, are heavier (GBs), slower to boot. Containers offer process-level isolation; VMs offer hardware-level isolation.
Q: What are key Docker commands for interviews?
docker build -t name ., docker run -d -p 8080:80, docker-compose up, docker exec -it, docker logs, docker ps. Understand layers, caching, multi-stage builds, and .dockerignore.
ContainerDockerfileMulti-stage build

Kubernetes ▼
Q: What are the core Kubernetes components?
Control Plane: API Server, etcd, Scheduler, Controller Manager. Worker Nodes: kubelet, kube-proxy, container runtime. Key objects: Pod, Deployment, Service, ConfigMap, Secret, Ingress, Namespace.
Q: What's the difference between a Deployment and a StatefulSet?
Deployment is for stateless apps, pods are interchangeable. StatefulSet provides stable network identities, persistent storage per pod, ordered deployment/scaling — needed for databases, Kafka, etc.
Q: How does a Service discover Pods?
Via Labels & Selectors. A Service selects pods by labels. ClusterIP gives internal VIP; NodePort exposes on each node; LoadBalancer provisions a cloud LB. DNS: service-name.namespace.svc.cluster.local.

🛡️ Resilience Patterns
🔍
Service Discovery ▼
Q: Client-side vs Server-side service discovery?
Client-side: client queries service registry directly (e.g., Eureka + Ribbon). Server-side: client calls a load balancer which queries registry (e.g., K8s Service, AWS ALB + Route53). Server-side is simpler for clients.
ConsulEurekaDNS

Circuit Breaker ▼
Q: Explain the Circuit Breaker pattern states.
Closed: normal operation, requests pass through. If failures exceed threshold → Open: requests fail-fast immediately. After a timeout → Half-Open: limited trial requests; if they succeed → Closed; if they fail → Open again. Prevents cascading failures.
Q: What tools implement Circuit Breakers?
Resilience4j (modern, Java), Hystrix (deprecated but famous), Istio/Envoy (sidecar-level), Polly (.NET). Often combined with fallback responses (cached data, default values).
Resilience4jHystrixFallback

Timeouts ▼
Q: What types of timeouts should you configure?
Connect Timeout: max time to establish TCP connection (short, ~1-3s). Read/Request Timeout: max time waiting for response after connection (depends on endpoint SLA). Always set timeouts — never rely on defaults (often infinite!).
ConnectReadSocket
🔁
Retries & Exponential Backoff ▼
Q: What is Exponential Backoff with Jitter?
After a failure, wait base × 2^attempt before retrying (e.g., 100ms, 200ms, 400ms...). Add random jitter to prevent thundering herd (all clients retrying simultaneously). Max retries & max backoff caps are essential.
Q: When should you NOT retry?
On non-transient errors (4xx client errors like 400/403), when the operation isn't idempotent (duplicate charges!), or when retries would exacerbate the problem (downstream already overloaded). Use idempotency keys.
JitterThundering HerdIdempotency
🔑
Idempotency ▼
Q: What is idempotency and how do you implement it?
An operation that produces the same result no matter how many times it's executed. Implementation: clients send an idempotency key (UUID); server stores key→response mapping. Duplicate requests return the cached response. Used by Stripe, PayPal for payments.
Idempotency KeyPaymentsStripe
📨 Messaging & Events

Message Queues ▼
Q: Message Queue vs Pub/Sub vs Event Stream?
MQ (RabbitMQ): point-to-point, consumers compete, message removed after ack. Pub/Sub (Google Pub/Sub): multiple subscribers receive each message. Event Stream (Kafka): durable log, multiple consumers can replay from any offset.
RabbitMQKafkaSQS
📢
Pub/Sub ▼
Q: How does Pub/Sub decouple services?
Publishers emit events to topics without knowing subscribers. Subscribers receive events they're interested in. This enables loose coupling, independent scaling, and easy addition of new consumers without modifying publishers.
DecouplingTopicsFan-out

Event-Driven Architecture ▼
Q: What is Event-Driven Architecture (EDA)?
Services communicate via events (facts that happened, e.g., "OrderPlaced"). Services react to events asynchronously. Enables loose coupling, scalability, and real-time reactivity. Often paired with Event Sourcing and CQRS.
EDAEvent SourcingCQRS

Distributed Transactions & Saga ▼
Q: Why avoid 2PC in microservices and what's the alternative?
Two-Phase Commit is blocking, slow, and doesn't scale. The Saga Pattern breaks a distributed transaction into local transactions, each with a compensating action (rollback). Two coordination styles: Choreography (events) and Orchestration (central coordinator).
Saga2PCCompensation

Dead Letter Queue (DLQ) ▼
Q: What is a DLQ and when is it used?
A queue for messages that couldn't be processed successfully after all retries. Allows investigation, manual reprocessing, or automated handling of poison messages without blocking the main queue. Critical for observability.
DLQPoison MessageSQS
📡 Communication Patterns
🔌
WebSockets ▼
Q: How do WebSockets differ from HTTP?
WebSocket is a full-duplex, persistent connection. Starts as HTTP upgrade (101 Switching Protocols), then becomes a bidirectional TCP tunnel. Ideal for chat, live feeds, gaming. HTTP is request-response; WebSocket allows server push anytime.
Full-DuplexSocket.ioReal-time

Long Polling ▼
Q: What is Long Polling?
Client sends HTTP request; server holds it open until data is available or timeout. Client immediately re-requests. Simulates real-time without WebSockets. Used when WebSockets aren't supported. Less efficient than WebSockets but simpler.
HTTPCometFallback

Server-Sent Events (SSE) ▼
Q: SSE vs WebSockets?
SSE is unidirectional (server→client only), uses standard HTTP, auto-reconnects, simpler. WebSockets are bidirectional. Use SSE for live dashboards, notifications, stock tickers. Use WebSockets for chat, collaborative editing.
SSEEventStreamUnidirectional

Webhooks ▼
Q: What are Webhooks?
User-defined HTTP callbacks: when an event occurs, the source makes an HTTP POST to a configured URL. Used for integrations (Stripe payment notifications, GitHub push events). Requires the receiver to have a public endpoint.

🗄️ Database Fundamentals
📇
Database Indexing ▼
Q: How do B-Tree indexes work and why are they common?
B-Trees maintain sorted data with O(log n) search/insert/delete. They're balanced, self-organizing, and optimized for disk I/O (each node fits a disk page). Support range queries efficiently. Most relational DBs default to B+Tree.
Q: What is a Covering Index?
An index that contains all columns needed by a query, so the DB never needs to read the actual table (index-only scan). Dramatically faster. Order matters: put equality-filter columns first, then range columns.
B+TreeCompositeClustered

Query Optimization ▼
Q: How do you approach slow query optimization?
1. Use EXPLAIN ANALYZE to see the execution plan. 2. Look for sequential scans on large tables → add indexes. 3. Check for missing WHERE clauses, inefficient JOINs. 4. Avoid SELECT *, use proper JOIN types. 5. Consider denormalization or materialized views.
EXPLAINExecution PlanPostgreSQL

N+1 Query Problem ▼
Q: What is the N+1 query problem?
Fetching a list of N entities, then executing N additional queries for each entity's associations. Instead of 1 JOIN query, you make N+1 queries. Solution: Eager Loading (JOIN FETCH, .Include(), preload) or batch loading.
ORMEager LoadingJOIN FETCH

Connection Pooling ▼
Q: Why is connection pooling critical?
Creating DB connections is expensive (TCP handshake, TLS, auth). A pool reuses established connections. Key settings: max pool size, connection timeout, idle timeout, max lifetime. Tools: HikariCP (Java), PgBouncer (PostgreSQL), RDS Proxy.
HikariCPPgBouncerRDS Proxy
📖
Read Replicas ▼
Q: How do Read Replicas help scale databases?
Writes go to the primary; reads are distributed across read replicas. This offloads read-heavy workloads. Trade-off: replication lag means replicas may serve slightly stale data (eventual consistency). Use when read volume >> write volume.
ReplicationRead ScalingLag
🧩
Sharding ▼
Q: What is Sharding and how do you choose a shard key?
Splitting data across multiple independent databases (shards). Shard key determines which shard holds which data. Good keys have high cardinality and even distribution. Avoid hot shards. Challenges: cross-shard queries, rebalancing, JOINs are hard.
HorizontalShard KeyVitess
📊
Partitioning ▼
Q: Sharding vs Partitioning?
Partitioning splits a table into smaller pieces within the same database (e.g., by date range). Sharding distributes data across separate database instances. Partitioning helps with query performance & data management; sharding helps with write scalability.
RangeListHash
📋
Replication ▼
Q: Synchronous vs Asynchronous replication?
Synchronous: primary waits for replica confirmation before committing → strong consistency but higher latency. Asynchronous: primary commits immediately, replicas catch up → faster but risk of data loss on failover. Semi-synchronous: at least one replica confirms.
BinlogWALFailover

Leader Election ▼
Q: How does Leader Election work?
In a cluster, one node is elected leader to coordinate work (e.g., Kafka controller, DB primary). Uses consensus algorithms like Raft or Paxos. Tools: ZooKeeper (ephemeral znodes), etcd (leases). Heartbeats detect leader failure → new election.
RaftZooKeeperetcd
🔺
CAP Theorem ▼
Q: Explain the CAP Theorem.
In a distributed system, during a network partition (P), you must choose between Consistency (C) — all nodes see the same data — and Availability (A) — every request gets a response. You can't have both during a partition. Most systems are CP or AP; CA doesn't exist in distributed systems.
Brewer'sCP vs APNetwork Partition
⏰
Eventual Consistency ▼
Q: Eventual Consistency vs Strong Consistency?
Strong Consistency: after a write, all subsequent reads return the latest value (linearizability). Eventual Consistency: given enough time with no new writes, all replicas converge. BASE (Basically Available, Soft state, Eventually consistent) vs ACID.
BASEDynamoDBCassandra
🔓
Optimistic Locking ▼
Q: How does Optimistic Locking prevent lost updates?
Each row has a version number. On update: UPDATE ... SET version = version + 1 WHERE version = expected_version. If zero rows affected, someone else modified it → retry or fail. Good for low-contention scenarios. No locks held.
Version ColumnCASLow Contention
🔒
Pessimistic Locking ▼
Q: When to use Pessimistic over Optimistic Locking?
Use pessimistic (SELECT ... FOR UPDATE) when contention is high and conflict probability is significant. Locks the row, blocking other writers. Trade-off: reduced concurrency, risk of deadlocks. Optimistic is better for read-heavy, low-conflict workloads.
FOR UPDATERow LockHigh Contention
🔐
Distributed Locks ▼
Q: How to implement a distributed lock and what are the pitfalls?
Use Redis (SET NX PX with unique token, Lua script for safe release) or ZooKeeper/etcd (ephemeral sequential znodes). Pitfalls: clock skew, GC pauses causing lock expiry while holder still thinks it has the lock. Use fencing tokens to prevent this.
RedisRedlockFencing Token
⚔️
Race Conditions & Deadlocks ▼
Q: How do you prevent deadlocks?
Lock ordering: always acquire locks in a consistent global order. Lock timeout: don't wait indefinitely. Deadlock detection: periodically check for cycles in wait-for graph. Avoid nested locks when possible. Use tryLock() with timeouts.
MutexLock OrderingtryLock

Memory Leaks & Garbage Collection ▼
Q: What causes memory leaks in GC languages?
Unintentional object references preventing GC: static collections growing unbounded, unclosed resources (connections, streams), listener/callback registrations never removed, thread-local variables in pooled threads, large off-heap allocations.
GCHeap DumpMark-Sweep

Thread Safety ▼
Q: How do you ensure thread safety?
Use immutable objects, synchronization (synchronized blocks, locks), atomic classes (AtomicInteger, AtomicReference), concurrent collections (ConcurrentHashMap), volatile for visibility, ThreadLocal for per-thread state. Prefer higher-level abstractions over raw locks.
ConcurrentHashMapAtomicvolatile

Backpressure ▼
Q: What is Backpressure in streaming systems?
When a producer is faster than the consumer, backpressure signals the producer to slow down, preventing overwhelming the consumer or running out of memory. Implemented in Reactive Streams (RxJava, Project Reactor), RSocket, and Kafka consumer polling.
ReactiveFlow ControlRSocket

Autoscaling & Horizontal/Vertical Scaling ▼
Q: Horizontal vs Vertical Scaling?
Vertical (scale up): bigger machine (more CPU/RAM). Simple but has limits, single point of failure. Horizontal (scale out): more machines. Better scalability, fault tolerance, but requires distributed system design. K8s HPA auto-scales pods based on CPU/memory/custom metrics.
HPAK8sScale Out
🌍
CDN & Edge Caching ▼
Q: How does a CDN reduce latency?
CDNs cache content at edge locations (PoPs) geographically close to users. Static assets (images, CSS, JS) are served from the nearest edge, reducing round-trip time. Also reduces origin server load. Examples: Cloudflare, CloudFront, Akamai, Fastly.
CloudFrontCloudflarePoP

Cache Invalidation ▼
Q: What are common cache invalidation strategies?
TTL (time-to-live), event-driven purge (invalidate on data change), write-through (update cache on write), stale-while-revalidate (serve stale while refreshing in background). Watch for cache stampede — many concurrent cache misses overwhelming the DB.
TTLStale-While-RevalidateStampede
🚀 Deployment Strategies
🚩
Feature Flags ▼
Q: What are Feature Flags and their use cases?
Toggles that enable/disable features at runtime without redeploying. Use cases: dark launches, canary testing, kill switches, A/B testing, gradual rollouts. Tools: LaunchDarkly, Flagsmith. Always clean up stale flags to avoid technical debt.
LaunchDarklyDark LaunchKill Switch
🔵🟢
Blue-Green Deployments ▼
Q: How does Blue-Green deployment work?
Maintain two identical environments: Blue (current live) and Green (new version). Deploy to Green, test thoroughly, then switch all traffic at once via load balancer. Instant rollback: switch back to Blue. Doubles infrastructure cost during deployment.
Zero DowntimeInstant Rollback
🐤
Canary Releases ▼
Q: What is a Canary Release?
Gradually shift a small percentage of traffic (e.g., 5%) to the new version while monitoring metrics. If healthy, increase to 25%, 50%, 100%. If issues detected, rollback immediately. Minimizes blast radius. Often combined with feature flags.
GradualBlast RadiusIstio
🔄
Rolling Deployments ▼
Q: How do Rolling Deployments work in Kubernetes?
Pods are updated incrementally, a few at a time. Controlled by maxSurge (extra pods allowed during update) and maxUnavailable (pods that can be down). Default in K8s Deployments. No extra infrastructure needed, but slower rollback than Blue-Green.
K8smaxSurgeIncremental
⏪
Rollbacks ▼
Q: What makes a safe rollback?
Backward-compatible database migrations (additive only, no destructive changes in same deploy), feature flags for instant disable, immutable artifacts (rollback to known-good version), and automated rollback triggers based on error rate spikes.
K8sBackward CompatibleDB Migrations
📊 Observability & Monitoring
💚
Health Checks & Probes ▼
Q: Liveness vs Readiness vs Startup probes in K8s?
Liveness: "Am I alive?" — if fails, K8s restarts the pod (deadlocked apps). Readiness: "Am I ready to serve traffic?" — if fails, pod removed from service endpoints (warming up, overloaded). Startup: for slow-starting apps, delays liveness/readiness checks.
K8sLivenessReadiness
📊
Monitoring, Logging & Distributed Tracing ▼
Q: What are the three pillars of observability?
Metrics: numerical data over time (Prometheus). Logging: structured event records (ELK, Loki). Tracing: follows a request across services (Jaeger, Zipkin, OpenTelemetry). Together they enable debugging complex distributed systems.
OpenTelemetryJaegerPrometheus
🎯
SLOs, SLIs & Error Budgets ▼
Q: Define SLI, SLO, and Error Budget.
SLI (Service Level Indicator): measured metric (e.g., 99.5% availability). SLO (Objective): target for SLI (e.g., 99.9%). Error Budget: 100% - SLO = acceptable downtime (e.g., 0.1% = ~43 min/month). Error budgets guide release velocity — if you're within budget, you can deploy.
SREGoogle SREAvailability

Secrets Management ▼
Q: Why shouldn't secrets be in code or env vars?
Code repos leak, env vars are visible in process listings/debug endpoints. Use HashiCorp Vault, AWS Secrets Manager, or K8s Secrets (with encryption at rest). Rotate secrets automatically. Use dynamic secrets when possible (short-lived, per-request).
VaultAWS Secrets ManagerRotation
🪪
IAM, OAuth & JWT ▼
Q: Explain OAuth 2.0 flow and JWT.
OAuth 2.0: authorization framework. Client gets an access token (via authorization code, client credentials, etc.). JWT: JSON Web Token — self-contained, signed token with claims. Access tokens (short-lived) authorize API calls; refresh tokens (long-lived) obtain new access tokens.
OAuth2JWTOIDC

Security Essentials ▼
Q: Quick definitions of common security terms?
TLS: encrypts data in transit. Encryption at Rest: encrypts stored data (AES-256). WAF: Web Application Firewall filters HTTP traffic. DDoS: Distributed Denial of Service. CORS: browser security for cross-origin requests. CSRF: forged requests from other sites. XSS: injecting malicious scripts. SQL Injection: injecting SQL via user input. SSRF: tricking server into making requests to internal systems.

🏗️ Infrastructure & Data Management
📦
Database Migrations & Schema Versioning ▼
Q: How do you safely manage database schema changes?
Use migration tools (Flyway, Liquibase, Alembic) with versioned migration scripts. Expand-Contract pattern: 1) Add new column (expand), 2) Dual-write, 3) Migrate data, 4) Remove old column (contract) in a separate deploy. Never make breaking changes in a single release.
FlywayExpand-ContractAlembic

Disaster Recovery, Failover & Multi-Region ▼
Q: What are RTO and RPO?
RTO (Recovery Time Objective): max acceptable downtime. RPO (Recovery Point Objective): max acceptable data loss (time). Active-Passive: cheaper, slower failover. Active-Active (Multi-Region): faster, more expensive. Regular DR testing is essential.
RTORPOActive-Active

Chaos Engineering ▼
Q: What is Chaos Engineering?
Deliberately injecting failures into production (or staging) to verify system resilience. Start small (kill one pod), observe, expand blast radius. Tools: Chaos Monkey (Netflix), Gremlin, LitmusChaos. Proves that your redundancy actually works.
Chaos MonkeyGremlinResilience
🌍 Networking & Protocols
⏱️
Latency, Throughput & P99 ▼
Q: Why is P99 latency more important than average?
Averages hide outliers. P99 (99th percentile) means 1% of users experience worse latency. In large systems, tail latency amplifies: if a request touches 100 services, the chance of hitting a P99 slow service is ~63%! Optimize for P99/P999.
P99Tail LatencyPercentile
🌐
DNS, TCP/UDP, HTTP/2 & HTTP/3, gRPC ▼
Q: TCP vs UDP? HTTP/2 vs HTTP/3?
TCP: reliable, ordered, connection-oriented. UDP: fast, no guarantees, good for streaming/gaming. HTTP/2: multiplexing, header compression, server push (over TCP). HTTP/3: uses QUIC (UDP-based), faster handshakes, no head-of-line blocking. gRPC: uses HTTP/2, Protocol Buffers, great for microservices.
QUICgRPCProtobuf
🕐
Clock Skew & Network Partitions ▼
Q: Why is clock skew problematic in distributed systems?
Different servers have slightly different times (NTP drift). Can't rely on timestamps for ordering events. Use Lamport timestamps or vector clocks for causal ordering. Network partitions (split-brain) require careful handling — use quorum-based decisions.
NTPLamportSplit-Brain

API Versioning & Semantic Versioning ▼
Q: How do you version APIs?
Strategies: URL path (/v1/users), header (Accept: application/vnd.api+json;version=1), query param. SemVer: MAJOR.MINOR.PATCH — bump MAJOR for breaking changes, MINOR for new backward-compatible features, PATCH for fixes.
SemVerBreaking ChangeDeprecation

Infrastructure as Code & Terraform ▼
Q: What is IaC and why Terraform?
IaC manages infrastructure via declarative code, enabling versioning, reproducibility, and automation. Terraform uses HCL, maintains state, plans changes before applying. Helm Charts package K8s manifests. Avoid manual console changes — they drift and aren't reproducible.
TerraformHelmState

Build Caching & Dependency Hell ▼
Q: How to speed up builds and avoid dependency conflicts?
Docker layer caching: copy dependency files first, then source. Incremental builds. Dependency lock files (package-lock.json, go.sum, Cargo.lock) ensure reproducible builds. Dependency hell: conflicting transitive dependencies — use lock files, version pinning, and regular updates.

Production Incidents & On-call ▼
Q: What's a good incident response process?
Detect (monitoring/alerting), Respond (acknowledge, escalate), Mitigate (stop the bleeding — rollback, scale, kill switch), Resolve (fix root cause), Postmortem (blameless, focus on learning). Tools: PagerDuty, Opsgenie. Runbooks automate common responses.
PagerDutyRunbookEscalation
📝
Postmortems ▼
Q: What makes a good postmortem?
Blameless culture — focus on systems and processes, not individuals. Document timeline, impact, root causes, action items with owners and deadlines. Share publicly within the org. The goal is learning and preventing recurrence, not punishment.
BlamelessRCAAction Items
⏰
Cron Jobs ▼
Q: What are Cron Jobs and their pitfalls?
Scheduled tasks running at fixed times/intervals (cron expressions). Pitfalls: overlapping runs (use locking), missed runs (server down), timezone issues, silent failures (need alerting). For distributed systems, ensure only one instance runs (leader election or DB lock).
ScheduledCron ExpressionK8s CronJob

Cold Starts & Serverless Limits ▼
Q: What is a cold start in serverless?
When a serverless function (AWS Lambda) hasn't been invoked recently, the cloud provider must initialize a new execution environment — download code, start runtime, run init code. This adds latency (100ms–several seconds). Mitigation: provisioned concurrency, smaller packages, faster runtimes.
LambdaWarm StartProvisioned

Cost Optimization ▼
Q: Key strategies for cloud cost optimization?
Right-sizing (match resources to actual usage), Reserved/Savings Plans (commit for discount), Spot instances (cheap but interruptible), Auto-scaling (scale down when idle), Delete unused resources, Storage tiering (S3 Intelligent-Tiering), Tagging for accountability.
FinOpsSpotRight-sizing
